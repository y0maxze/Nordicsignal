# Verified NewsWeb historical research adapter

Official source reference: Euronext's Oslo market page links NewsWeb as the company-announcement service: https://www.euronext.com/en/markets/oslo . The public NewsWeb application (https://newsweb.oslobors.no/) loads `/urls.json`, whose `api_large` points to `https://api3.oslo.oslobors.no`. Public client bundle `main.b50249e5.js` uses read-only POST requests to `/v1/newsreader/list` with `fromDate`/`toDate` (YYYY-MM-DD), and `/v1/newsreader/message` with `messageId`. No credentials, undocumented guessed hosts, or browser security bypass were used.

Live validation on 2026-09-27: the exact one-day query for 2026-09-17 returned 140 rows and `overflow=false`. Strict matching selected one Techstep financing notice (message 682643). Fetching its body with the new adapter produced partial labelled terms and correctly left dilution unknown because compatible exact pre-issue/new-share counts were absent. The source body is plain text, not synthetic HTML. Only extracted bounded terms and a body hash are retained, not the complete publisher body.

An older month query exposed a concrete identity hazard: a historic title named one company while current issuer metadata named another. Consequently, ingestion requires exact ticker, unique current issuer identity, and a matching issuer title prefix. Test records, foreign markets, mismatched legal AS/ASA suffixes, missing IDs, unknown publication times and future messages are rejected. Generic titles and renamed historical issuers can be omitted; coverage is explicitly partial.

The protected background wakeup processes one calendar day per run, prioritising an hourly revisit of today, then earlier days up to 730 calendar days. Durable leases recover interrupted windows and prevent expired workers from committing. Failed/truncated windows are eligible for daily retry. Truncation, queried days, failed days and stored-document date bounds are exposed separately. These bounds do not prove continuous issuer coverage or absence of financing risk.

Document enrichment verifies message ID, issuer ID, ticker, company name, title, publication time, test flag and correction references against the stored announcement before extracting any terms. Explicit `correctedByMessageId` is shown as a source-provided correction link; documents are not inferred to belong to the same transaction. Unsupported HTML/PDF/unstructured documents remain unsupported or partially interpreted. Main score, Opportunity, High Conviction, sizing, push rules and credentials are unchanged.

This is a verified public-client contract, not a contractual API availability guarantee. Format changes fail closed. PWA shell v21. Authenticated production browser/PWA/push verification remains blocked by the Cloudflare robot-verification page observed earlier in this session.
